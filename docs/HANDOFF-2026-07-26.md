## 4. Data work — corporate actions

### The problem

538 unexplained price discontinuities in the adjusted panel.

### What was built

- **`scripts/build_security_master.py`** → `data/reference/security_master.parquet`
  from `data/nse_raw/ohlcv_raw.parquet` (which already carries `isin`/`series`).
  `classify_isin()`: `INE`→equity, `INF`→fund/ETF, `IN0`/`IN9`→govt.
  Output: 6,787 rows, 4,130 ISINs, 4,053 symbols, 432 renames, 537 reused tickers.

- **`src/sepa_scanner/data_sources/ca_purpose.py`** — `parse_purpose()` returns
  `ParsedAction(multiplier, kind, detail)`. Handles face-value changes and
  bonuses, multiplying both legs on combined strings. **Refuses** demergers,
  buybacks, bare ratios, and degenerate face values.

- **`scripts/reconcile_corporate_actions.py`** — buckets every discontinuity by
  evidence strength, while separating `complex_action` and `long_hiatus` rows
  that must not be inferred as one-session split factors.

The central rule — text and price must corroborate each other:

```python
# The parsed multiplier is only trusted when the observed price move agrees
# with it. Text alone could be a stale or misdated filing; price alone
# could be a real collapse. Together they corroborate each other.
agrees = pl.col("parsed_residual").is_not_null() & (
    (pl.col("parsed_residual") - pl.col("ratio")).abs()
    <= purpose_tolerance * pl.col("parsed_residual").abs()
)
```

### Result

**Quarantine 538 → 87.** The final reconciliation is 71 manual, 9 reviewed
complex actions, and 7 long-hiatus boundaries, with zero inferable rows.
The override ledger contains 454 rows: 268 purpose-parsed, 140 ISIN-corroborated,
43 independently reviewed manual corrections, 1 ETF inference, and 2
corroborated inert seeds.

The 71-row residual is the diminishing-return tail: 63 rows predate 2010. Seven
of the eight later rows are documented scheme/demerger or rename boundaries
that cannot be represented by a single-symbol factor; `VIVIDHA` (2015-05-28)
is the only later jump without corroborating evidence.

**Parity remains 12.48% / 24.28% / 0.51 / 281.**

## 7. Bugs found and fixed (the substantive ones)

These are worth reading — several were caught by arithmetic, not by tests.

1. **SOTM silently produced 0 trades / 0.00%.** An empty regime frame was read
   as "no buys allowed", turning the whole strategy into a no-op that still
   reported a tidy flat curve. My plan under-specified this. Now it raises with
   a message naming both remedies, and `regime_source` is an explicit enum
   (`price_index` | `nifty500_tri`).

2. **Phantom lot trades** — 21,859 trades at an 851-day average hold. Exhausted
   lots were never pruned, so they matched zero shares and still emitted a trade
   dated from their original entry. Caught by arithmetic: 18.6M implied
   position-days against ~87,600 available. Fixed with a `remaining > 0` guard
   in `portfolio_order_engine.py:63`; the new test was verified to fail without it.

3. **Win-rate population mismatch** in `lab/metrics.py` — numerator from
   `r_values`, denominator from `pnl_values`. Latent, but fixed with a shared
   `basis`.

4. **`_load_ca_overrides` honoured only `source == "manual"`** — 118 inferred
   rows would have been written and silently ignored. Fixed with
   `APPLIED_CA_SOURCES` plus a hard error on unrecognised sources, because "an
   override row that is written but never applied is invisible".

5. **`event_price_multiplier` ignored `adjustment_factor`** — every inferred row
   returned `None` and was skipped, so GOLDBEES kept its 100× cliff after a
   "successful" rebuild.

6. **Double adjustment via the anti-join** — keyed on
   `(symbol, ex_date, action_type)`, so an override `split` stacked on a feed
   `bonus`. Changed to `(symbol, ex_date)`.

7. **Override ex-date mismatch** — overrides used the observed jump date, the
   feed used its own up to 3 days off, so both applied. Caught by arithmetic
   (expected ~173 residual, got 268). Fixed with
   `pl.coalesce([pl.col("ca_date"), pl.col("date")])`.

8. **`max_jump=4.0` was blind to ratio 0.5** — 1:2 splits and 1:1 bonuses sit
   inside the band. Now each seed is checked against its own stated factor.
   Verdict: 4 of 6 legacy `seed` rows are genuinely wrong (IRCTC off by a year,
   DMART/TCS/BAJFINANCE); RELIANCE and HDFCBANK are valid. `seed` stays excluded.

9. **Circular dependency in the reconciler** — it classifies whatever panel is on
   disk, so classifying an already-double-adjusted panel looped back to the
   start. Fixed with a strict sequence and a baseline check that must report 538.

10. **Rebuilt without `--dividends` by mistake**, silently converting
    total-return → price-return across 4.1M rows / 1,622 symbols. My error. The
    safety check passed because it only asked "is this explicable", not "is this
    intended".

### Claims I made and later corrected

Recorded here so the next agent does not inherit them:

  CA feed via `PREVCLOSE(t)/CLOSE(t-1)`. Disproved on NIFTYBEES

### Resolved API persistence race

`tests/lab/test_store_and_api.py::test_run_completes_end_to_end_through_the_api`
failed because the API observed `status="done"` after equity had been inserted
but before trades were persisted. `LabStore.save_result()` updated the run first,
then wrote its child rows in separate autocommitted statements.

The preserved failure output disproved the lock hypothesis: the job completed,
the equity curve contained more than 100 rows, and only `body["trades"]` was
empty. Result persistence is now one explicit transaction, with `done` used as
the final publication flag. A deterministic concurrent-reader test pauses the
trade insert and asserts that readers still see `running` with no partial child
rows until commit.
